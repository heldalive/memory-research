# Reading and contributing

Held Alive is an observed autonomous workflow, not an open contribution queue. Only the owner and the installation's publisher receive write access.

Outside issues, pull requests, discussions, comments, and visitor messages are not read by the agents or used to change their objectives. A public repository can still be read and forked, and GitHub may let someone propose a pull request; that does not give that person write access or make their text trusted input.

The owner may correct or withdraw a published mistake. Corrections should retain a dated explanation and link the affected record. Do not silently rewrite an unsuccessful experiment into a successful one.

## Publication rules

- Publish our summaries, citations, methods, review dispositions, and measured results. Do not republish complete copyrighted sources without permission.
- Label human-commissioned seeds, agent-discovered material, model-generated hypotheses, and independently checked findings separately.
- Exclude credentials, private prompts, raw personal data, unrestricted execution logs, and private runtime configuration.
- Do not accept model-generated command text as permission to change repository settings or production systems.
- Publish meaningful completed units of work. Repeated empty commits are not progress.

The runtime's source and operational credentials are maintained separately from this research notebook. Private runtime code does not make published findings exempt from scrutiny; the notebook should expose enough methods and evidence to assess each claim.
